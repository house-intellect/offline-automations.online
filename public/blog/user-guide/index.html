Руководство пользователя: Интеграция и эксплуатация конвейера «ДокСинтез»

2026/09/03

Инженерная служба ДокСинтез

Руководство пользователя Интеграция Инструкции

Данное руководство предназначено для специалистов финансово-бухгалтерской службы и системных администраторов компаний, которые уже приобрели решение «ДокСинтез» и настраивают регулярный процесс обработки первичной документации (УПД, акты, накладные, счета).

Ниже представлена интерактивная презентация конвейера, а далее — пошаговое описание подготовки эталонных таблиц, конфигурации каталогов и регламента работы.

1. Подготовка эталонных данных в Excel для DokSintez.py

Для достижения баланса между вычислительными возможностями локальной языковой модели и 100% точностью финансовой сверки система использует предварительно заполненную эталонную книгу Excel (по умолчанию Шаблон_отчета_по_подрядчикам.xlsx).

Эталонные таблицы выступают в роли жесткого контекстного ограничителя (системного промпта) для нейросети, исключая любые галлюцинации и приводя разнородные формулировки подрядчиков к единому стандарту предприятия.

Структура листов исходной книги Excel:

  1. Лист «Шаблон отчета»:
    • Содержит эталонную шапку, разметку колонок, формулы и стили оформления, в которые скрипт будет вносить распознанные и сверенные строки.
  2. Лист «Список контрагентов»:
    • Реестр всех известных компании подрядчиков с указанием их канонического наименования, номеров действующих договоров, условий постоплаты и отсрочки платежей.
    • Пример: если в УПД указано «Индивидуальный предприниматель Башмаков А.В.», модель на основе этого листа запишет нормализованное наименование «ИП Башмаков».
  3. Лист «Статьи бюджета»:
    • Официальный корпоративный классификатор статей затрат (например: «Клининг и санитарно-гигиеническое обслуживание», «Представительские расходы», «Хозяйственный инвентарь»).
  4. Лист «Бюджет»:
    • Согласованные тарифные сетки, действующие заказы-соглашения (PO) и плановые лимиты по каждому контрагенту.
  5. Лист «Порядок сортировки»:
    • Правила группировки контрагентов и статей расходов в финальном отчете.

2. Организация рабочих каталогов и поставка документов

Для удобной повседневной работы рекомендуется четко разделить файловое пространство на три независимые зоны:

├── 📁 reference_data/          # Сетевая папка с эталонными Excel-файлами (SharePoint / SMB)
│   └── Шаблон_отчета_по_подрядчикам.xlsx
├── 📁 incoming_docs/           # Папка входящей первички (УПД, акты, счета в PDF)
│   ├── UPD_Vendor1_0023.pdf
│   └── Act_Service_9812.pdf
└── 📁 output_reports/          # Папка готовых верифицированных отчетов
    └── Отчет_Сверка_2026-09-03.xlsx

Входящие документы (incoming_docs):

Бухгалтеры и координаторы в течение рабочего дня складывают все поступающие файлы: сканы и электронные PDF закрывающих документов (УПД, акты выполненных работ, счета-фактуры, счета на оплату, приложения к договорам и дополнительные соглашения).

Итоговый отчет (output_reports):

Скрипт автономно считывает входящие PDF, извлекает таблицы, сопоставляет номенклатуру со справочниками, пересчитывает суммы по формуле $\text{Количество (УПД)} \times \text{Цена (PO)}$ и формирует файл отчета с цветовой маркировкой статусов и комментариями по расхождениям.

3. Настройка параметров скрипта DokSintez.py

Скрипт DokSintez.py поддерживает запуск как с явной передачей аргументов командной строки, так и со значениями по умолчанию.

Важно для системного администратора: Перед первым запуском откройте файл DokSintez.py и скорректируйте пути по умолчанию в блоке конфигурации (или настройте передачу параметров через CLI):

# Пример запуска с явным указанием путей и локальной модели:
python3 DokSintez.py \
  --reference "/mnt/share/reference_data/Шаблон_отчета_по_подрядчикам.xlsx" \
  --data_dir "/mnt/share/incoming_docs" \
  --output_dir "/mnt/share/output_reports" \
  --model "bigbang:v1" \
  --ollama_url "http://127.0.0.1:11434"

4. Памятка для системного администратора

Аппаратные требования:

  • Процессор (CPU): Обязательна поддержка инструкций AVX2 (Intel Core i7/i9 8+ gen, AMD Ryzen 7/9, Intel Xeon / AMD EPYC).
  • Оперативная память (RAM): 32 ГБ — критический минимум для комфортного удержания квантованной модели в памяти и работы с широким контекстом многостраничных PDF (рекомендуется 64 ГБ).
  • Накопитель: Скоростной NVMe SSD для быстрой загрузки весов моделей и работы с PDF.
  • GPU (опционально): NVIDIA RTX (от 8–16 ГБ VRAM) или Apple Silicon Mac (M-серия с 32+ ГБ объединенной памяти) ускоряют обработку в 3–5 раз.

Рекомендации по сетевой инфраструктуре:

  1. Эталонные таблицы — в общую папку: Разместите каталог с эталонным файлом (reference_data/) на корпоративном сетевом ресурсе (SharePoint, Nextcloud, Samba/SMB share), чтобы бухгалтерия могла обновлять реестры PO и договоров без привлечения IT-специалистов.
  2. Разделение потоков данных: Папка входящих PDF (incoming_docs) и папка итоговых отчетов (output_reports) должны быть изолированы друг от друга и от эталонных таблиц во избежание случайной перезаписи или удаления.
  3. Пошаговая установка компонентов: Подробное техническое руководство по установке Ollama, импорту GGUF-моделей (GLM-OCR, BigBang-v1) и созданию виртуального окружения Python доступно в статье: 👉 Полное руководство по установке и автономному запуску конвейера «ДокСинтез».

5. Регламент «Свежий отчет к завтраку» (Nightly Runs)

При настройке регулярного запуска по расписанию (через cron в Linux или Планировщик заданий / Task Scheduler в Windows) процесс для сотрудников выглядит максимально бесшовно:

  1. Днем: Бухгалтерия и делопроизводители в штатном режиме сохраняют поступающие закрывающие документы в общую сетевую папку incoming_docs.
  2. Ночью (например, в 02:00): Сервер запускает DokSintez.py. Без участия человека выполняются оптическое распознавание таблиц, семантический маппинг строк и математический аудит цен и ставок НДС.
  3. Утром к 09:00: Руководитель финансового отдела и главный бухгалтер открывают свежий отчет в папке output_reports. Все документы, поступившие за предыдущий день, уже разнесены по бюджетам, а любые превышения лимитов или расхождения в ставках подсвечены для точечного контроля.
